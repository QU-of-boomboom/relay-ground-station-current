# FPGA无线地面站：PDR、RTT、AoI融合持续告警

本仓库保存当前在FMQL30TAI开发板上使用的地面站源码：节点通过无线网络发送报文，板端PS负责接收、协议处理和测量证据整理，FPGA负责链路质量判定与融合持续告警。结果通过板端终端查看。

当前版本日期：**2026-10-22**。

## 当前版本包含什么

- 基于PS工作搬迁前的工程，保留官方PL侧AI_Mate、MIG及公共平台依赖。
- 在该基线上加入PDR、RTT、AoI融合持续告警，告警由FPGA判断。
- 保留原PS端报文核对与逐包结算，不启用后续PS迁移到PL的实验路线。
- 包含当前板端接收程序、原生寄存器访问代码、UIO适配、热点配套源码和独立节点发送程序。
- 包含2026-10-22的RTT样本过期边界修复；此次软件修复没有修改RTL或位流。
- 网页界面已弃用；RSSI接入、NPU交互与推理、进一步PS迁移暂停。

AI_Mate是PL侧配套逻辑，不能与芯片专用NPU本体混为一谈。保留其硬件依赖不代表本项目已使用NPU推理。

## 系统如何工作

```text
节点发送程序 → 节点USB网卡 → 无线链路 → 板端USB网卡
                                              ↓
                                    PS接收报文、核对发送记录
                                    整理RTT/AoI时间区间证据
                                              ↓ UIO/MMIO
                                    FPGA维护PDR窗口与质量判定
                                    融合PDR、RTT、AoI
                                    处理持续触发、恢复和失效
                                              ↓
                                    PS读取FPGA结果、终端打印
```

PS仍承担网络和协议处理：本版本没有把无线报文直接送到PL，也没有把所有测量工作都交给FPGA。PS负责准备证据，FPGA负责质量及持续告警判定。

当前发送端使用明确标记为`synthetic`的测试计数器和协议记录，不是无人机传感器数据。RTT是软件收发链路的往返测量；AoI使用测试数据的因果时间区间，不宣称是飞控同步时钟下的精确数据年龄。

## FPGA工程使用说明

使用与FMQL30TAI匹配的**Vivado 2018.3及厂家数据库/补丁环境**打开`FPGA/fpai_demo_vivado.xpr`。不要用未经适配的普通Xilinx安装替代当前工具环境。

保留工程内的宏、时钟、约束、IP和Tcl钩子。主要源码通过`PPRDIR`、`PSRCDIR`相对引用；XPR中仍可能保留原工程的绝对路径元数据，迁移机器后需要核对工具与路径配置。

本仓库是源码副本，**不含综合布线缓存、DCP、位流、BOOT或整张SD镜像**。打开XPR后没有历史运行记录是正常的，不代表源码没有完成过综合布线。

`toolchain_lock.json`记录原F173工具环境与基线，不是当前导出目录的完整文件清单。当前源码来源和校验值见`source_manifest.json`及`SHA256SUMS`。

## 板端和发送端运行条件

- 板端实际环境：Ubuntu 20.04、AArch64、厂家Linux 5.4.52；当前接收程序使用Python 3.11.17。
- PS源码包含需要Python 3.10及以上版本的语法，不能直接使用该系统自带的Python 3.8运行。
- 需要匹配的地面站位流、UIO设备、原生MMIO库及设备权限；普通电脑上不能代替实板执行寄存器测试。
- 无线部分依赖板端匹配的8821cu、cfg80211等模块、hostapd、dnsmasq和配套配置。本包没有收录完整厂家内核、全部驱动及私有热点配置。
- 节点发送端需要正确的无线连接、本地IP、板端IP、端口、节点身份、会话身份和独立密钥。

查看入口参数，不启动接收或访问硬件：

```sh
python3 PS/runtime/push_worker.py --help
python3 Sender/node_sender.py --help
```

接收入口的`--candidate`应指向本包的`PS`目录，使其找到`software/pdr`。还需要显式提供配置、输出目录、映射参数及原生库路径和SHA256；使用前按当前板端环境配置。

`config.example.json`仅展示结构：示例IP、全零nonce及身份值必须替换，不能直接作为实际会话配置。每次会话须分配合法新身份并配置独立密钥。密钥不写入仓库，也不通过命令行参数明文传递。

发送周期参数`--period-ms 50`对应每秒20包。发送程序与接收程序独立运行；停止板端接收不等于停止节点发送。

本包尚未提供经过验证的一键终端会话配置器，不把源码整理完成等同于新板一键部署完成。

## 查看结果与正确停止

在板端使用匹配的Python解释器，读取当前会话日志：

```sh
python3 PS/runtime/print_board_quality.py /实际会话目录/dashboard.jsonl
```

该工具只读取日志，不打开UIO，也不额外发起FPGA寄存器事务。它显示最近一次硬件采样及年龄；历史`CLEAR`不能当作当前仍有效的硬件授权。

| 要停止什么 | 操作 | 结果 |
|---|---|---|
| 结果打印 | 在打印终端按`Ctrl+C` | 只结束查看，不停止接收 |
| 板端接收 | 向接收进程的控制stdin输入`STOP`，或在其前台终端按`Ctrl+C` | 触发停止、排空、撤销及资源释放 |
| 节点发送 | 在发送端前台终端按`Ctrl+C` | 结束该节点发送程序并关闭其网络资源 |

接收程序停止后应等待`done`记录并检查清理结果，不能看到打印停止就认为接收已经停止。正常退出不要用直接拔电或`kill -9`代替。

`UNAVAILABLE`表示证据、时效或有效资格不足，不等于“无告警”。持续告警需要有效输入满足持续条件；不能把过期的良好结果一直保留为正常状态。

`implementation_summary.json`是历史实现报告摘要。其中`board_tested=false`记录的是报告生成时尚未上板的状态，后来实板验证范围以上表为准。位流能够生成或实板能运行，不等同于整板时序已通过。
